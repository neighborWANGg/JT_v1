# 酒桶研判系统 V1.5

酒桶研判系统是一套在本地使用的辅助研判工具。数据按案件分开，工作按研判对话进行。这一版在 V1.4 的图谱和研判流程上，补上了好友表、群聊归属、好友碰撞和重点群标记。

模型输出只作辅助。正式结论需要人工复核。

## 更新内容

### 材料导入

- 人工识别可以一次选择多个 `.xlsx`。
- 好友表文件名使用 `姓名_微信号.xlsx`，例如 `张三_wxid_example.xlsx`。系统据此识别这是谁的微信。
- 群聊文件名使用 `姓名_群聊.xlsx`。系统据此识别这批群来自谁的微信。
- 系统只根据已经上传的材料判断人员，不会自行假定哪些人已经到案。文件归属人，以及备注为「本人」的人员，视为已导入人员。

### 群聊原始数据

- 材料导入后即可查看群聊原始数据和图谱，不必先做材料智能分析。
- 群列表第一行是群号。能识别来源时，显示「某人的微信」及对应账号；识别不到时显示「来源未识别」。
- 单个群最多显示最近 5000 条消息。超过这个数量时，会注明当前只显示最近多少条。

### 重点群

材料智能分析会把重点群标出来。下面两个条件满足一个即可，两个都满足也会标出：

- 同一个群里出现两名及以上已导入人员。
- 群内容撞上案件的重点关键词，或根据简要案情判断为可能相关。

分析前可以先看原始数据和图谱。重点标记和结论文字在点击「材料智能分析」之后写入。

### 微信好友筛查

- 勾选多人后，对所有人的好友做交集碰撞。两个人共同的好友也会列出来，不要求所有被勾选的人都有这个好友。
- 碰撞按同一栏比较：微信ID 对微信ID，微信号对微信号，原始账号对原始账号。某一栏有一侧是空的，就跳过这一栏，不用另一栏去补。
- 至少有一栏两边都有值并且相同，才算同一个好友。昵称、备注不参与合并。
- 碰撞结果标题显示微信号相关字段，不显示对方昵称。出现在哪些人的好友中，用已导入人员的姓名列出。两人之间的关系卡片仍使用姓名。

### 图谱与笔记

- 图谱在尚未缩放、平移时，会按人物节点收紧显示范围。用户自己拖动或缩放之后，不再改视野。
- 人员关系数按双向关系统计。
- 案件笔记保存在当前案件里。换浏览器打开同一案件，仍能看到已保存的笔记。
- 采纳、修改、驳回在页面内填写，不再使用浏览器弹窗。

## 使用流程

### 1. 启动

在本目录准备好 Python 环境后，双击 `启动后台.bat`。后台已在运行时，脚本只会打开工作台。

- 工作台：<http://127.0.0.1:8765/ui>
- 接口文档：<http://127.0.0.1:8765/docs>

首次使用可手动安装并启动：

```powershell
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

健康检查地址是 <http://127.0.0.1:8765/health>，正常返回 `{"status":"ok"}`。

### 2. 新建案件

点击左侧「新建案件」，填写：

| 字段 | 作用 |
| --- | --- |
| 案件名称、案件编号 | 区分案件 |
| 案件类型、承办人、承办单位 | 案件基本信息 |
| 简要案情 | 供后续判断哪些群可能相关 |
| 重点关键词 | 多个词用顿号或逗号分隔，用于标记重点群 |

创建后进入该案件。

### 3. 导入材料

在准备工作里点「人工识别」，一次选中需要的表格。单个文件不超过 50 MB。同一文件按 SHA-256 识别，不会重复导入。

好友表建议命名为 `姓名_微信号.xlsx`，表内使用这些列：

| 列名 | 含义 |
| --- | --- |
| 好友微信ID | 好友的微信 ID |
| 好友微信号 | 好友的微信账号 |
| 好友原始账号 | 好友的原始账号 |
| 呢称 / 好友昵称 | 好友昵称，只用于展示 |
| 好友备注 | 备注，不参与好友合并 |

群聊表建议命名为 `姓名_群聊.xlsx`，表内至少包含群号、发送方账号和聊天内容。可用列名包括 `群号(GROUP)`、`发送方账号ID(SENDID)`、`聊天内容(CONTENT)`，也兼容 `群ID`、`微信号`、`聊天内容`。

导入完成后，顶部可以切换「群聊原始数据」和「图谱」。

### 4. 查看群和图谱

- 「群聊原始数据」：先看群号和来源微信，再点进群看消息。
- 「图谱」：查看已导入人员及其关系。滚轮或按钮可缩放，拖动画布可平移，拖动人物节点可调整位置。
- 右侧「微信好友筛查」：勾选要比较的人员，点击「筛查好友」。结果里看共同好友的微信字段，以及两人之间是否互为好友。

### 5. 材料智能分析

1. 在案件下新建研判对话。案件里只有一个对话时，进入案件会自动打开它。
2. 点击「材料智能分析」。系统按简要案情、重点关键词和已导入人员，标出重点群并生成结论文字。
3. 在结果里核对证据原文。需要复核时，使用页面内的采纳、修改或驳回。
4. 右侧「案件笔记」可随时记录线索。停止输入后会保存到当前案件。

本地模型可通过 LM Studio 的 OpenAI 兼容接口接入，在案件设置里填写地址和模型名。未接入模型时，导入、群聊查看、图谱和好友筛查仍可使用；依赖模型生成的结论文字需要模型可用。

## 数据存放

```text
data/<case_id>/
├─ project.json
├─ conversations/
├─ agent/
└─ 导入的原始表格
```

数据库默认是 `data/jt.db`。案件笔记写在案件记录里。运行中的数据库、案件目录和密钥不要提交到版本库。

## 当前边界

- 没有登录和案件授权，只适合在受控环境使用。
- 好友碰撞不提供单独导出。
- 群聊消息按最近 5000 条显示，没有跨群全文检索。
- 页面上的「AI 识别」尚未开放。
